# Foundations of Information Systems  
## System Development Life Cycle (SDLC)  

SDLC is a structured approach for building or modifying information systems.  
It divides the work into phases to ensure control and quality.  

### Phases of SDLC
1. **Planning**  
   - Feasibility studies to decide if the project is viable.  
   - Types of feasibility:  
     - **Technical**: Are technical resources sufficient? Can the team implement it?  
     - **Economic**: Will the system bring financial benefit compared to cost?  
     - **Operational**: Will users accept it and does it solve key problems?  

2. **Analysis**  
   - Understand business requirements and create a logical model of the system.  
   - **Requirements determination**:  
     - Investigation: study and document current system.  
     - Specification: define features and requirements for new system.  
   - **Information gathering techniques**:  
     - Interviews (structured/unstructured)  
     - Document analysis (records, procedures)  
     - Questionnaires (open or closed)  
     - Observation of system in use  
   - **System Analyst**:  
     - Acts as mediator between users and technical team.  
     - Roles: problem analysis, system study, design assistance, training users.  
     - Skills:  
       - Interpersonal: communication, leadership, teamwork.  
       - Analytical: problem-solving, system study.  
       - Management: project, change, and risk management.  
       - Technical: knowledge of IT, design tools, new technologies.  

3. **Design**  
   - Move from “what” (analysis) to “how” (solution).  
   - **Types of design**:  
     - **Logical design**: abstract representation of inputs, outputs, data flow.  
     - **Physical design**: details of input, processing, output, interfaces.  
   - Decisions include: programming language, hardware/software, network, database, user interface, backup, training.  
   - Tools: Data Flow Diagram (DFD), Entity-Relationship Diagram (ERD), Data Dictionary, Decision Tables/Trees.  
   - **ER Model**: defines entities, relationships, attributes.  

4. **Implementation**  
   - Convert design into working system.  
   - Steps:  
     - **Coding**: translate specifications into programs.  
     - **Testing**:  
       - Program test: individual components.  
       - System test: whole system with real data.  
     - **Acquisition/Installation**: hardware and software setup.  
     - **Conversion**: migrate old data into new system.  
     - **Training**: teach users how to use system.  
     - **Documentation**: record all details for future reference.  

5. **Maintenance**  
   - Continuous updates to ensure the system stays useful.  
   - Tasks:  
     - Replace outdated hardware.  
     - Update software to handle new security threats.  
     - Evaluate performance and fix issues.
